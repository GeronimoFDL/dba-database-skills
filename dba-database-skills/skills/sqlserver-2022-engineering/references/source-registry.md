## Conflictos y límites de verificación

- **Clustered por defecto:** Microsoft favorece clustered para muchas tablas. Se conserva como punto de partida contextual; no se transforma en una migración automática de todas las tablas.
- **Mantenimiento:** se prioriza la guía de diseño/mantenimiento actual sobre umbrales heredados de fragmentación. No se atribuye a Microsoft la inexistencia de casos donde rebuild sea útil.
- **Query Store secundario:** la tabla de ediciones enumera la capacidad; la nota de versión S02 declara preview no soportada para producción 2022. Se aplica esta última restricción.
- **CIS:** S90 acredita disponibilidad del benchmark SQL Server 2022 v1.3.0 en el catálogo. No se consultó su PDF completo ni se afirma cumplimiento de controles específicos. Las reglas técnicas de seguridad se sostienen en Microsoft y OWASP. Una evaluación formal requiere obtener la edición/perfil aplicable y mapear control a evidencia.
- **.NET:** guías transversales; verificar versiones efectivas de cliente/ORM antes de prescribir APIs. S87 trata ADO.NET; no traslada automáticamente todos sus detalles de implementación a cualquier driver.
- **Convenciones/proceso:** nombres de constraints, estructura de entrega, revisión y expand/contract son criterios de ingeniería expresados como tales. No se presentan como mandatos del motor.
- **Documentación mixta:** ejemplos con AdventureWorks2025, json nativo, OPPO, optimized locking, PSP para DML y automatic index compaction no se reutilizan como SQL Server 2022.
